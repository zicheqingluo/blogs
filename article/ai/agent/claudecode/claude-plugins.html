    # Everything Claude Code

    来自 Anthropic 黑客马拉松获胜者的完整 Claude Code 配置集合。

    不止是配置文件，而是一整套完整系统：技能体系、本能行为、记忆优化、持续学习、安全扫描，以及研究优先的开发模式。 包含可直接用于生产环境的智能体、技能模块、钩子、规则、MCP 配置，以及兼容传统命令的适配层——所有内容均经过 10 个多月高强度日常使用与真实产品开发迭代打磨而成。

    可在 Claude Code、Codex、Cursor、OpenCode、Gemini 及其他 AI 智能体框架中通用。

    github:点击github (opens new window)

/plugin marketplace add https://github.com/affaan-m/ECC

    # 第二步：仅在需要时安装规则

    (opens new window)

    WARNING: 重要提示： Claude Code 插件无法自动分发 rules。

    如果你已经通过 /plugin install 安装了 ECC，不要再运行 ./install.sh --profile full、.\install.ps1 --profile full 或 npx ecc-install --profile full。插件已经会自动加载 ECC 的技能、命令和 hooks；此时再执行完整安装，会把同一批内容再次复制到用户目录，导致技能重复以及运行时行为重复。

    对于插件安装路径，请只手动复制你需要的 rules/ 目录。只有在你完全不走插件安装、而是选择“纯手动安装 ECC”时，才应该使用完整安装器。

# 插件安装路径：只复制规则
mkdir -p ~/.claude/rules 
cp -R rules/common ~/.claude/rules/
cp -R rules/typescript ~/.claude/rules/

# 纯手动安装 ECC（不要和 /plugin install 叠加）
# ./install.sh --profile full

    # Ralph Wiggum Plugin

    Ralph 是一种基于连续 AI 代理循环的开发方法论。正如 Geoffrey Huntley 所描述的：“Ralph 是一个 Bash 循环”——这是一个简单而真实的说法，它会反复向 AI 代理输入提示文件，使其能够迭代改进工作直到完成。

    该技术以《辛普森一家》中的拉尔夫·维格姆命名，体现了即使遇到挫折仍坚持迭代的哲学。

    该插件通过一个停止钩子实现了 Ralph，该钩子拦截了 Claude 的退出尝试：

    循环发生在你当前会话中 ——你不需要外部的 bash 循环。hooks/stop-hook.sh 中的 Stop hook 通过阻断正常会话退出，形成自我指涉的反馈循环。

    This creates a self-referential feedback loop where:
    这形成了一个自指反馈循环 ，其中：

    • The prompt never changes between iterations
      提示词在迭代之间从不改变
    • Claude's previous work persists in files
      克劳德以往的工作仍存于文件中
    • Each iteration sees modified files and git history
      每次迭代都会看到修改的文件和 git 历史
    • Claude autonomously improves by reading its own past work in files
      Claude 通过读取自身过去的工作文件自动改进
    # 第一步安装插件

    这是官方插件，打开claude-code执行命令安装即可

    /plugin install ralph-loop

    # 使用

    命令行输入指令，tab键选中，空格写入提示词，不要有换行符 /ralph + [Tab]

    # claude-code-zh-cn

    Claude Code 是一个很棒的终端 AI 编程助手，但它没有中文界面。当前 stable 支持窗口内，UI 文字主要硬编码在一个 13MB 的 cli.js 里，没有 i18n 基础设施。

    官方短期内不太可能加中文支持。所以我做了这个插件，通过四层机制（设置注入 + Hook 系统 + 插件系统 + CLI Patch）实现中文化，自动检测安装方式，更新后自动修复。

    github:点击打开github (opens new window)

    # 第一步安装

    依赖node

    curl -fsSL https://github.com/taekchef/claude-code-zh-cn/releases/latest/download/install-remote.sh | bash

    # Superpowers

    从你启动编码代理的那一刻起就开始了。一旦它看到你在构建东西， 它不会直接跳到写代码。相反，它会退一步，问你到底想做什么。

    github:GitHub - obra/superpowers: An agentic skills framework & software development methodology that works. · GitHub (opens new window)

    # 第一步安装

    从claude官方安装：

    /plugin install superpowers@claude-plugins-official

    # 使用
    brainstorming - Activates before writing code. Refines rough ideas through questions, explores alternatives, presents design in sections for validation. Saves design document.
头脑风暴 ——在写代码前启动。通过提问完善粗略的想法，探索替代方案，并将设计分成章节进行验证。保存设计文档。

using-git-worktrees - Activates after design approval. Creates isolated workspace on new branch, runs project setup, verifies clean test baseline.
using-git-worktrees - 设计批准后激活。在新分支创建隔离工作区，运行项目设置，验证干净的测试基线。

writing-plans - Activates with approved design. Breaks work into bite-sized tasks (2-5 minutes each). Every task has exact file paths, complete code, verification steps.
写作计划 ——通过批准设计激活。把工作分成小任务（每份 2-5 分钟）。每个任务都有精确的文件路径、完整的代码和验证步骤。

subagent-driven-development or executing-plans - Activates with plan. Dispatches fresh subagent per task with two-stage review (spec compliance, then code quality), or executes in batches with human checkpoints.
子代理驱动开发或执行计划 ——随计划激活。每个任务派遣新子代理，进行两阶段审查（规范合规，然后代码质量），或通过人工检查点批量执行。

test-driven-development - Activates during implementation. Enforces RED-GREEN-REFACTOR: write failing test, watch it fail, write minimal code, watch it pass, commit. Deletes code written before tests.
测试驱动开发 ——在实施过程中激活。强制执行 RED-GREEN-REFACTOR：写失败测试，观察它失败，写最小代码，观察它通过，提交。删除测试前编写的代码。

requesting-code-review - Activates between tasks. Reviews against plan, reports issues by severity. Critical issues block progress.
请求代码审查 ——在任务间激活。与计划进行审查，按严重程度报告问题。关键问题阻碍了进展。

finishing-a-development-branch - Activates when tasks complete. Verifies tests, presents options (merge/PR/keep/discard), cleans up worktree.
完成开发分支 ——任务完成时激活。验证测试，提供选项（合并/PR/保留/丢弃），清理工作树。

    # claude-mem

    Claude-Mem 通过自动捕捉工具使用观察、生成语义摘要并提供给后续会话，无缝保存了会话间的上下文。这使得 Claude 即使在会议结束或重新连接后，仍能保持项目知识的连续性

    # How It Works  工作原理

    (opens new window)

    Core Components:  核心组成部分：

    1. 5 Lifecycle Hooks - SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd (6 hook scripts)
      5 个生命周期钩子 - SessionStart、UserPromptSubmit、PostToolUse、Stop、SessionEnd（6 个钩子脚本）
    2. Smart Install - Cached dependency checker (pre-hook script, not a lifecycle hook)
      Smart Install - 缓存依赖检查器（预于钩子脚本，非生命周期钩子）
    3. Worker Service - HTTP API on port 37777 with web viewer UI and 10 search endpoints, managed by Bun
      工作服务 - 位于 37777 端口的 HTTP API，带有网页查看器界面和 10 个搜索端点，由 Bun 管理
    4. SQLite Database - Stores sessions, observations, summaries
      SQLite 数据库 - 存储会话、观测值、摘要
    5. mem-search Skill - Natural language queries with progressive disclosure
      记忆搜索技能 ——自然语言查询，具渐进披露
    6. Chroma Vector Database - Hybrid semantic + keyword search for intelligent context retrieval
      色度向量数据库 - 混合语义+关键词搜索，实现智能上下文检索

    github:claude-mem (opens new window)
